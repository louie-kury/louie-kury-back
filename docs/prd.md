## 1. 문서 목적과 읽는 방법

본 문서는 각 기능을 개발할 때 에이전트와 사람이 함께 읽는 **제품 정책·요구사항의 기준 문서**다. 서비스 전체 범위와 기능별 기대 동작, 공통 정책, 미정 질문, QA의 연결을 관리한다. 특정 기술 스택, DB 구조, 서비스 분리 방식은 확정하지 않는다.

### 1.1 기준과 우선순위

- **[확정]**: 제공된 PRD v1.1에서 확정으로 다룬 요구사항이다. 이번 편집에서 최초 기획서와 독립 대조하거나 새로운 외부 검토를 완료했다는 뜻은 아니다.
- **[미정]**: 제공된 PRD에서 미확정인 항목이다. 해당 정책에 의존하는 작업에 착수하기 전에 사용자 또는 사람이 지정한 제품·운영 담당자에게 질문하고, 답변을 문서에 반영한 뒤 구현한다. 담당 분야 이름은 결정권자 지정이 아니다.
- 6장의 기능별 요구사항은 7장 상태·금전 처리, 8장 정보 접근, 10장 공통 품질 정책과 함께 적용한다. 화면 목록(9장), 정보 관계(11장), QA(14장)는 이를 추적하며 독립적으로 운영 정책을 추가하지 않는다.
- 최신으로 문서에 반영된 사람의 결정이 변경 이력과 연결되어 기준이 된다. 코드·테스트·화면 시안·에이전트의 추측으로 기존 요구사항을 덮어쓰지 않는다. 절 사이에 충돌이 남으면 해당 부분을 미해결로 기록하고 사람에게 확인하며, 임의로 우선순위를 골라 구현하지 않는다.
- 초기 출시 범위는 4장 전체다. 미정 항목이 있다는 이유로 기능을 임의 삭제하거나 MVP로 축소하지 않는다.

### 1.2 미정 처리와 개발 요청의 단위

미정 항목에는 권장 기본값이 없다. 가격·코인 환산, 입력 단위·허용 범위, 취소 기한, 권한 세부 범위, 내부 상태명(enum), DB·기술 스택을 개발자가 임의 확정하지 않는다. 특정 사례나 데이터 항목의 등장만으로 허용 범위·상태·보관 기간을 확정하지 않는다.

개발 요청에는 **기능 ID → 적용 공통 정책(절 번호) → 관련 D ID → 수용 기준·Q ID**를 함께 적는다. 6.11의 연결표와 12장의 질문 목록을 확인하고, 구현할 확정 범위와 답변을 기다릴 범위를 구분한다. 미정 정책에 의존하는 부분만 보류하고 독립적인 확정 작업은 진행할 수 있다. 사람의 답변이 오면 해당 D 항목과 관련 기능·상태·권한·QA를 함께 갱신한다.

수용 기준과 QA는 기대 동작이며 구현·검증 완료를 뜻하지 않는다. 미정 정책에 의존하는 기대값은 답변 후 구체화한다. 데이터 정합성과 타인 정보 접근 차단 등 기존 공통 품질 기준은 유지한다. 본 문서는 법률 검토, 결제 계약, 가상번호 연동 가능성 확인 또는 구현 검증의 결과물이 아니다.

## 2. 제품 목표

### 2.1 해결할 문제

1. 보호자가 반려동물의 건강 변화를 기억에 의존하여 관리하고 설명한다.
2. 상담이 필요해도 수의사를 찾고 건강 정보를 전달하는 과정이 분리되어 있다.
3. 상담 후 내용을 다시 확인하기 어려워 건강 관리의 연속성이 떨어진다.

### 2.2 제품 가치

**반려동물별 건강 기록 관리 → 지정 예약 또는 위치 기반 즉시 상담 신청 → 승인 또는 매칭 → 상담 → 상담 일지 확인**을 하나의 흐름으로 제공한다. 커뮤니티는 보호자와 수의사의 정보 교류를 지원하고, 유료 상담과 수수료 정산은 서비스 수익 구조를 구성한다.

### 2.3 성과 측정 [미정]

측정할 지표, 산식, 수치 목표, 집계 기간은 미정이다. 성과 측정 기능 개발 전 담당자에게 어떤 지표가 필요한지 질문한다.

## 4. 출시 범위

### 4.1 초기 출시 필수 범위 [확정]

- 보호자 가입과 계정 관리, 병원 소속 수의사의 병원 정보·병원 명의 사업자 계좌 등록, 면허 제출 및 관리자 승인
- 여러 반려동물 등록·관리, 강아지·고양이 지원
- 건강 기록 6종, 사진 등 미디어 첨부, 예방접종 및 병원 진료 이력
- 건강 기록의 달력형·목록형 조회
- 수의사 목록·프로필·평점·후기 확인 및 직접 선택
- 지정 수의사에게 희망 날짜·시간으로 예약 요청, 승인·거절·취소·완료
- 보호자 위치와 동물병원 간 거리를 기준으로 수의사에게 알리고, 최초 수락자 한 명에게 연결하는 즉시 상담
- 상담 상태별 건강 기록 접근 제어, 채팅·화상통화·수의사가 거는 안심번호 전화 상담
- 상담 완료 확인창에서 담당 수의사의 보호자 신고, 상담 일지 작성·공유, 별점 및 선택적 텍스트 후기
- 코인 충전·예약 차감·취소 및 거절 반환, 결제·코인 이력 구분
- 플랫폼 수수료 산정 및 등록된 병원 명의 사업자 계좌로 정산
- 커뮤니티 게시글·댓글·대댓글·좋아요·미디어·신고
- 회원·인증·상담·결제·정산·커뮤니티·신고 관리자 기능

### 4.2 초기 범위에 포함하지 않는 항목

- [확정] 강아지·고양이 외 동물 지원은 향후 확장한다.
- [미정] 건강 그래프·통계는 도입 여부 결정 전까지 출시 필수 범위에서 제외한다.

범위 밖 기능이 필요해지면 별도 변경 요청으로 영향과 완료 기준을 정의한다.

## 5. 주요 사용자 흐름

### 5.1 보호자

가입 → 반려동물 등록 → 건강 기록 작성 → 수의사 탐색 → 상담 대상 반려동물·희망 일시·상담 내용 입력 → 요금 및 정보 공유 안내 확인 → 상담 신청 버튼 선택 → 상담 수단 선택 및 요청 제출 → 코인 차감 → 승인 확인 → 예약 시각에 상담 연결 → 수의사 완료 처리 → 상담 일지 조회 → 별점·후기 작성

**위치 기반 즉시 상담**은 신속한 상담이 필요한 상황에 이용한다. 보호자가 상담 신청 버튼을 누르고 수단을 선택해 요청을 제출하면 가까운 여러 동물병원에서 즉시 상담 요청 대기 화면을 띄운 수의사의 실시간 목록에 해당 요청을 동시에 표시한다. 최초 수락자가 확정될 때 코인을 차감하고 선택한 수단으로 연결한다. 이후 상담 완료·일지·후기는 공통 흐름을 따른다.


### 5.2 수의사

가입 시 소속 병원 정보·병원 명의 사업자 계좌 입력 및 면허 제출 → 관리자 심사 → 승인 → 예약 요청 확인 → 요약 정보 검토 → 승인 또는 거절 → 승인된 반려동물 건강 기록 열람 → 상담 연결 → 완료 처리 및 기록 접근 종료 → 상담 일지 작성·공개 → 정산 내역 확인

위치 기반 즉시 상담에서는 수의사가 즉시 상담 요청 대기 화면을 띄우고 기다린다. 본인에게 전달된 요청을 실시간 목록에서 확인하고 원하는 요청을 선택해 수락한다. 최초 수락자로 확정되면 보호자와 상담을 시작한다.

### 5.3 관리자

면허 심사 → 회원 및 상담 운영 확인 → 결제·코인 반환 예외 처리 → 상담 수익·수수료·정산 검토 → 지급 결과 관리 → 신고 검토 및 조치

## 6. 기능 요구사항과 수용 기준

각 항목의 [확정]은 제공 PRD의 요구사항을 보존한 것이며, 수용 기준은 그 기대 동작이다. [미정] 문장과 질문은 구현 지시가 아니다. 실제 구현·검증 완료를 의미하지 않는다. 모든 기능에는 10장의 공통 품질 요구사항이 적용되며, 기능별 연결은 6.11을 따른다.

### 6.1 회원·수의사 인증 — ACC

**ACC-01 회원 계정**

- [확정] 보호자·수의사·관리자 유형과 계정 상태를 구분한다.
- [미정] 가입 방식, 본인 및 연락처 확인 방식, 비밀번호 정책, 소셜 로그인 제공 여부를 결정한다.
- **수용 기준:** 로그인하지 않은 사용자는 타인의 반려동물·지갑·상담 정보를 열람할 수 없다. 역할이 다른 사용자가 관리자 기능을 호출하면 거부된다.

**ACC-02 수의사 가입·심사**

- [확정] 동물병원에 소속된 수의사만 수의사 계정으로 가입할 수 있다. 병원에 소속되지 않은 프리랜서 수의사는 가입할 수 없다.
- [확정] 수의사는 가입 신청 시 소속 병원의 **병원명, 사업자등록번호, 병원 주소, 대표자명**과 해당 병원 명의의 사업자 계좌를 필수로 등록한다. 병원 주소는 주소 검색 결과에서 선택해 입력한다.
- [확정] 정산 계좌의 예금주 확인에는 [금융결제원 오픈뱅킹 계좌실명조회 API](https://developers.kftc.or.kr/dev/openapi/open-banking/account)를 사용한다. 정산 계좌 등록과 심사에서 통장 사본은 수집하지 않는다.
- [확정] 수의사는 가입 시 면허증을 제출한다. 재직증명서는 제출 대상에서 제외한다. 관리자 승인 후 상담을 제공하거나 수의사 자격으로 활동할 수 있다.
- [미정] 사업자등록증 제출 여부, 재직증명서 없이 소속을 확인하는 방식, 주소 검색 제공 업체와 상세주소 입력 방식, 이직·퇴직 시 소속 변경 절차는 D11에서 확정한다. 금융결제원 이용계약·이용승인 가능 여부와 개인사업자·법인 계좌의 사업자등록번호 검증 지원 범위는 D02에서 연동 전에 확인한다.
- **수용 기준:** 병원명·사업자등록번호·병원 주소·대표자명 중 하나라도 빠지거나 병원 명의 사업자 계좌가 누락되면 가입 신청을 완료할 수 없다. 주소 검색 결과에서 선택한 주소가 병원 주소에 반영되고, 재직증명서 미제출로 가입 신청을 막지 않는다. 병원에 소속되지 않은 수의사는 승인 대상에서 제외한다. 대기·거절 수의사는 상담 제공 목록에 노출되지 않고 예약 승인도 할 수 없다. 관리자 심사 결과·처리자·처리 시각이 기록된다.

**ACC-03 정지·탈퇴와 진행 중 거래**

- [확정] 관리자는 회원 정지와 탈퇴 등 계정 상태를 관리한다.
- **수용 기준:** 정지된 수의사에게 신규 예약을 요청할 수 없다. 기존 승인 예약의 처리 방안 없이 예약이나 코인이 유실되지 않는다.
- [미정] 보호자 직접 탈퇴 절차, 잔여 거래 처리와 데이터 보관·삭제 정책.

[미정] 수의사 인증의 상세 상태·재심사·철회·면허 열람 범위 및 계정 겸용 여부는 개발 전에 질문한다.

### 6.2 반려동물 관리 — PET

**PET-01 등록·조회·수정**

- [확정] 한 보호자가 여러 반려동물을 등록하고 각각의 이력을 분리하여 관리한다.
- [확정] 기본 정보는 이름, 종, 품종, 생년월일, 성별, 중성화 여부, 체중이다.
- **수용 기준:** 강아지·고양이를 등록할 수 있다. 반려동물을 전환하면 기록·접종·진료·상담 목록도 해당 동물 기준으로 바뀐다. 다른 보호자의 반려동물 ID를 요청해도 접근할 수 없다.
- [미정] 반려동물 삭제·보관 처리 및 진행 중 상담과의 관계. 해당 기능 개발 전 사람에게 질문하고 정책을 확정한다.

### 6.3 건강 기록 — HLT

**HLT-01 기록 입력·관리**

- [확정] 음수량, 식사량, 체중, 구토, 배변, 상처를 기록한다. 유형별 상세 내용과 미디어를 연결한다.

[미정 — 기록 입력 기능 개발 전 질문]

- 각 유형의 필수값, 입력 단위, 소수점 정밀도, 허용 범위는 무엇인가?
- 구토·배변·상처의 상세 항목은 무엇이며, 발생하지 않은 상태도 기록하는가?
- 관찰 일시와 작성 일시를 어떻게 구분하고, 하루 여러 건을 허용하는가?
- 수정·삭제를 허용하는가? 프로필 체중과 체중 이력은 어떻게 연결하는가?

**수용 기준:** 확정한 유형별 필수값·단위·범위에 따라 입력을 검증하고, 반려동물별로 기록을 분리한다. 구체적인 경계값 검증은 답변 후 정의한다.


**HLT-02 달력·목록 조회**

- [확정] 달력의 날짜 선택으로 해당 날짜 기록을 조회하고, 목록으로도 조회한다.
- **수용 기준:** 같은 반려동물·날짜의 기록이 양쪽 화면에서 일치한다. 기록이 없는 날은 빈 상태를 표시한다. 수정·삭제 기능을 제공하기로 확정한 경우 그 결과도 양쪽 조회에 일치한다.

**HLT-03 예방접종·병원 진료 이력**

- [확정] 반려동물별 예방접종과 병원 진료 이력을 관리한다.
- **수용 기준:** 접종·진료 이력을 해당 반려동물에만 연결한다. 수의사의 접근은 건강 기록과 같은 권한 규칙을 따른다.
- [미정] 접종·진료의 필수 입력과 변경·삭제 범위(D12), 승인 후 포함할 구체적인 정보 범위(D05)는 해당 기능 개발 전에 질문한다.

**HLT-04 미디어**

- [확정] 건강 기록에 사진 등 미디어를 첨부한다.
- **수용 기준:** 제한 위반과 업로드 실패를 안내하고 재시도할 수 있다. 비공개 기록의 첨부파일은 주소만 알아도 열리지 않으며, 해당 상담의 완료로 종료된 권한만으로는 수의사가 새 파일을 조회할 수 없다. 다른 승인 예약이 남은 경우의 권한 판단은 D05 확정 후 검증한다.

[미정] 미디어 형식·개수·용량 제한은 업로드 기능 개발 전에 질문한다.

### 6.4 수의사 탐색 — VET

**VET-01 목록·프로필**

- [확정] 보호자는 승인된 수의사를 확인하고 직접 선택한다. 프로필은 실명·소속 병원·사진·소개·평균 평점·후기를 제공한다.
- **수용 기준:** 수의사 프로필에서 해당 수의사로 예약을 시작할 수 있다. 후기가 없으면 평점 0점 대신 ‘아직 후기 없음’을 표시한다. 정지·미승인 수의사는 신규 상담 대상으로 선택할 수 없다.

[미정] 검색 조건·정렬·페이지 조회 방식·프로필 수정 절차는 해당 기능 개발 전에 질문한다.

### 6.5 상담 신청·연결 — CON

**CON-01 지정 수의사 예약 요청**

- [확정] 보호자는 수의사, 본인 반려동물 한 마리, 희망 날짜·시간, 상담 내용을 선택·입력한다. 요청 시 코인을 차감한다.
- **수용 기준:** 잔액 부족·대상 동물 권한 없음·수의사 제공 불가 상태에서는 요청과 차감이 모두 발생하지 않는다. 같은 요청의 중복 제출·재시도로 예약과 차감이 중복되지 않는다.

**CON-02 승인·거절**

- [확정] 담당 수의사는 요청을 승인하거나 거절한다. 승인 후 해당 반려동물의 전체 건강 기록을 조회한다. 거절 시 코인을 전액 반환한다.
- **수용 기준:** 담당 수의사만 처리할 수 있다. 거절된 예약은 승인할 수 없다. 승인과 취소가 동시에 요청되어도 최종 상태는 하나이며 반환·차감 내역과 일치한다.

**CON-03 상담 수단**

- [확정] 지정 예약과 위치 기반 즉시 상담 모두 채팅, 화상통화, 안심번호 전화를 제공한다. 보호자가 상담 신청 버튼을 누르면 세 가지 수단을 보여준다. 보호자는 수단 하나를 선택한 뒤 요청을 제출한다. 전화 상담은 담당 수의사가 안심번호로 보호자에게 발신하고, 양측의 실제 전화번호는 서로에게 공개되지 않는다. 전화 상담에는 고정 종료 시간과 통화 시간에 따른 추가 요금이 없다.
- [미정] 상담 중 수단 변경, 채팅·화상통화의 상세 동작과 이력 보관, 각 수단의 제공 업체, 안심번호 발급·유효 기간·재연결 절차는 D06에서 확정한다.
- **수용 기준:** 두 신청 유형 모두 상담 신청 버튼을 누르면 세 가지 수단이 표시되고, 보호자가 선택한 수단으로 담당 수의사와 보호자가 연결된다. 제3자는 상담에 참여할 수 없다. 안심번호 전화는 수의사 발신, 보호자 수신, 양측 실제 번호 비노출을 실제 단말에서 확인한다. 연결 실패는 상담 완료로 처리하지 않는다. 보호자에게 “수의사와 연결하지 못했어요. 다시 연결해 주세요.”를 표시하고 재연결을 시도할 수 있게 한다. 재연결 이후 상담이 취소되면 차감한 코인을 전액 반환한다.

**CON-04 완료·취소**

- [확정] 지정 예약과 즉시 상담에서 담당 수의사가 ‘상담 완료’를 누르면 “상담을 무사히 마쳤나요?”라는 작은 확인창이 열린다. ‘완료’와 ‘보호자 신고’ 버튼을 제공한다. ‘완료’를 누르거나 보호자 신고가 접수되면 상담을 완료 처리하고 해당 상담의 일지 작성 화면으로 이동한다.
- [확정] 신고 대상은 해당 상담의 보호자다. 신고를 해당 상담과 연결해 관리자가 검토할 수 있도록 한다.
- [확정] 완료 즉시 해당 상담에 따른 전체 건강 기록 열람 권한이 종료된다. 지정 예약과 즉시 상담 모두 취소가 성립하면 해당 상담에서 차감한 코인을 전액 반환한다. 즉시 상담 매칭 전 취소는 잔액 변동 없이 처리한다.
- **수용 기준:** 완료와 함께 코인 사용이 확정되고 정산 대상으로 한 번만 반영된다. 완료 요청 재시도는 추가 수익을 만들지 않는다. 취소 성공 후 코인은 한 번만 전액 반환된다. 확인창을 여는 것만으로 상담 상태가 바뀌지 않는다. 담당 수의사만 해당 보호자를 신고할 수 있다. 접수된 신고를 관리자가 해당 상담과 함께 확인할 수 있다.
- [미정] 보호자 신고 사유와 입력 항목, 제출 실패 안내와 재시도 화면은 D04에서 확정한다. 거절·취소 후 기록·상담 연결 권한의 세부 처리 방식은 D04·D05·D06에서 확정한다. 완료된 상담의 권한 종료가 같은 수의사·동물의 다른 승인 예약 권한에 미치는 영향은 D05에서 확정한다.

**CON-05 위치 기반 즉시 상담**

- [확정] 보호자는 신속한 상담이 필요할 때 위치 기반 즉시 상담을 신청할 수 있다. 서비스는 보호자 위치를 기준으로 요청 접수 즉시(0초) 반경 500m를 탐색한다. 매칭 대기 중이면 접수 후 10초에 1km, 20초에 1.5km, 30초에 5km, 40초에 10km로 넓힌다. 마지막 10km 단계는 전체 기한인 60초까지 최대 20초간 유지한다. 매칭이 성립하면 즉시 탐색을 종료하고, 해당 요청은 다른 수의사의 실시간 대기 목록에서 즉시 사라진다. 수의사는 즉시 상담 요청 대기 화면을 띄운 채 기다린다. 각 단계에서 대상 병원에 소속되고 해당 화면을 띄워둔 수의사에게 요청을 동시에 전달한다. 화면에는 본인에게 전달된 유효한 요청이 실시간 목록에 추가되며 여러 요청을 함께 볼 수 있다. 반경이 넓어져도 이미 전달받은 수의사에게 같은 요청을 다시 보내지 않는다. 해당 수의사의 목록에는 기존 요청을 한 건만 유지하고, 새로 알림 대상이 된 수의사에게 요청을 보낸다. 수의사는 목록에서 원하는 요청을 선택해 수락한다. 지정 예약 또는 즉시 상담을 진행 중인 수의사는 해당 상담이 끝날 때까지 다른 즉시 상담을 수락할 수 없다. 상담을 마치고 즉시 상담 요청 대기 화면을 다시 열면 새 요청을 받을 수 있다. 다른 탭을 보고 있거나 화면이 잠긴 상태는 대기에 포함하지 않는다. 최초 수락자 한 명을 확정할 때 코인을 한 번 차감하고 보호자가 고른 수단으로 연결한다. 매칭 대기는 요청 접수부터 한 건당 최대 60초다. 한 요청 안에서 검색 범위를 넓히는 경우에도 전체 대기 시간은 60초를 넘지 않는다. 기한까지 매칭이 성립하지 않으면 코인 차감 없이 미매칭으로 종료한다. 만료되거나 보호자가 매칭 전에 취소한 요청은 수의사의 실시간 대기 목록에서 즉시 사라진다. 미매칭으로 종료되면 “지금 바로 상담할 수 있는 수의사를 찾지 못했어요.”라는 문구를 안내창에 표시한다. 안내창 모서리의 닫기(X)는 창만 닫는다. 보호자가 즉시 상담을 다시 요청하면 새 매칭을 시작한다. 수락 시 잔액이 부족하면 “코인이 부족해 상담을 연결할 수 없어요.”를 표시한다.
- [확정] 즉시 상담 요청 목록에는 보호자가 선택한 상담 수단, 반려동물 종류(강아지·고양이), 요청의 수락 가능 남은 시간을 표시한다. 남은 시간은 최초 요청 접수부터 적용되는 60초 기한을 기준으로 표시한다. 거리와 반려동물의 건강 요약·기록은 목록에 표시하지 않는다. 매칭이 성립해도 해당 즉시 상담으로 반려동물의 기존 건강 기록 열람 권한을 부여하지 않는다.
- [미정] 위치 확인 방법, 위치 권한을 거부했을 때의 처리, 거리 산정 방식, 단계별 알림 대상 수 제한, 화면을 벗어나기 전에 받은 요청의 수락 조건, 차감 실패와 매칭 후 취소 허용 조건은 D17에서 확정한다.
- **수용 기준:** 한 요청에 여러 수의사가 동시에 수락해도 담당 수의사는 한 명만 확정된다. 나머지 수의사에게 매칭 결과를 알려 중복 연결을 막는다. 대상 수의사의 알림과 보호자·담당 수의사 간 연결을 확인한다.

### 6.6 상담 일지·후기 — LOG / REV

**LOG-01 상담 일지**

- [확정] 수의사는 상담 종료 후 일지를 작성하고 해당 보호자와 수의사가 계속 열람한다.
- **수용 기준:** 완료된 본인 담당 상담에만 일지를 작성할 수 있다. 공개된 일지는 해당 보호자와 담당 수의사만 조회하며, 일지 조회가 다른 건강 기록 접근 권한을 부여하지 않는다. 건강 기록 링크나 첨부파일이 권한 종료를 우회하지 않는다.
- [미정] 작성 기한, 지연 시 운영 대응, 공개 절차, 공개 후 수정·삭제·보관 기간(D07).

**REV-01 평가·후기**

- [확정] 보호자는 완료된 상담에 대해 평가할 수 있고, 별점은 필수·텍스트는 선택이다. 평점과 후기를 프로필에 표시한다.
- **수용 기준:** 해당 예약 보호자만 완료 이후 작성할 수 있다. 별점 없이 저장할 수 없고 별점만으로는 저장할 수 있다. 동일 요청 재시도로 후기가 중복 생성되지 않는다. 평균 평점과 평가 수가 실제 공개 대상 평가와 일치한다.
- [미정] 상담당 허용 평가 수, 별점 범위, 후기 수정·삭제 가능 기간, 숨김 처리된 후기의 평균 평점 반영 정책(D16).

### 6.7 결제·코인 — PAY

**PAY-01 충전과 지갑**

- [확정] 실제 결제로 코인을 충전하고 잔액, 충전·사용·반환 내역을 조회한다. 실제 결제 거래와 코인 원장을 구분한다.
- [확정] 7,000코인 충전 상품의 실제 결제액은 7,700원이다. 공급가액은 7,000원이고 부가세는 700원이다. 결제가 성공하면 7,000코인을 지급한다.
- [미정] 결제 업체·수단, 다른 충전 상품과 환산 기준, 부가세 처리 방식, 코인 유효 기간, 충전 한도(D01).
- **수용 기준:** 결제창 성공 화면만으로 코인을 지급하지 않는다. 같은 결제 결과의 중복 통지·재조회에도 1회만 충전된다. 외부 승인 후 내부 지급 실패를 감지하고 복구할 수 있다.

**PAY-02 차감·반환 정합성**

- [확정] 지정 예약과 즉시 상담은 상담 1건당 7,000코인을 차감한다. 채팅·화상통화·안심번호 전화와 수의사에 따라 요금이 달라지지 않는다. 지정 예약은 시간에 따라 차등 과금하지 않으며 요청 즉시 차감하고 거절·취소 시 전액 반환한다.
- [확정] 즉시 상담은 최초 수락자 확정 시 코인을 한 번 차감한다. 미매칭 또는 매칭 전 취소는 잔액 변동 없이 처리한다. 매칭 후 취소가 성립하면 실제 차감액을 전액 반환한다.
- [미정] 즉시 상담 수락 시 차감 실패와 매칭 후 취소 허용 조건은 D17에서 확정한다.
- **수용 기준:** 신청 유형과 상담 수단을 바꿔도 상담 1건의 요금은 7,000코인이다. 잔액이 한 건 요금만 가능한 상황에서 두 예약을 동시에 요청하면 최대 한 건만 성공한다. 반복 취소·거절 통지에도 한 번만 반환된다. 반환 금액은 현재 요금이 아닌 해당 예약의 실제 차감 코인이다.

**PAY-03 충전 결제 취소·현금 환불**

- [확정] 상담 취소에 따른 코인 반환과 충전 결제 취소·현금 환불은 별개로 관리한다.
- [확정] 기획상 충전한 코인을 전혀 사용하지 않았다면 현금 환불을 신청할 수 있다. 충전한 코인을 일부라도 사용했다면 잔액의 현금 환불을 제한한다.
- [미정] 환불액·수수료·기한·수단, 여러 충전 건에서 사용액을 배정하는 기준, 상담 취소로 코인을 돌려받은 경우의 환불 자격은 D10에서 결정한다. 일부 사용 후 환불 제한은 적용 법령과 예외를 확인한 뒤 실제 운영에 적용한다.
- **수용 기준:** 현금 환불 성공 시 해당 코인 회수와 실제 결제 취소 내역이 연결된다. 사용 중인 잔액과 동시 환불이 충돌해 코인이 중복 사용되거나 음수가 되지 않는다. 외부 환불 실패를 성공으로 표시하지 않는다.

### 6.8 수익 정산 — SET

**SET-01 수익 산정·지급 관리**

- [확정] 완료된 유료 상담 수익을 플랫폼 수수료와 수의사 정산 금액으로 구분한다.
- [확정] 완료된 상담 1건의 정산 기준액은 7,000원이다. 플랫폼 수수료는 **20%인 1,400원**이고, 수의사 배분액은 **80%인 5,600원**이다. 수의사 배분액은 등록된 소속 병원 계좌로 지급한다. 충전 결제액에 포함된 부가세 700원은 정산 배분에 포함하지 않는다.
- [확정] 매월 25일에 정산한다. 정산 금액이 확정되면 수의사가 가입할 때 등록한 소속 병원 명의 사업자 계좌로 자동 이체를 요청한다.
- [미정] 정산 대상 기간과 마감 시점, 25일이 휴일일 때의 처리, 지급 연동 업체, 계좌 입력 항목, 병원 명의 확인·계좌 변경 기준, 소속 변경 시 기존 상담의 지급 계좌, 이체 실패 후 재시도 절차, 세금·증빙, 결제대행 수수료 부담, 정산 환산·반올림, 최소 지급 금액(D02).
- **수용 기준:** 거절·취소·미완료 상담이 정산에 포함되지 않는다. 동일 상담의 재집계와 지급 재시도가 중복 정산을 만들지 않는다. 산정 기준 금액과 수수료·수의사 배분액을 대사할 수 있고 수의사는 본인 정산만 조회한다. 25일 정산 완료 후 등록된 소속 병원 명의 사업자 계좌로 지급을 요청하고, 이체 성공 확인 후 지급 완료로 표시한다. 이체 실패를 기록하고 재시도 시 중복 지급을 막는다.

### 6.9 커뮤니티 — COM

**COM-01 게시글·댓글·반응**

- [확정] 보호자와 수의사가 게시글·댓글·대댓글을 작성하고 좋아요·미디어 첨부·신고 기능을 사용한다.
- [미정] 게시판·카테고리, 비로그인 열람 범위, 게시판별 작성 권한, 삭제된 부모 댓글 표시 방식.
- **수용 기준:** 타인의 글을 수정·삭제할 수 없다. 좋아요 중복 요청으로 수가 증가하지 않는다. 삭제·숨김 게시글에 새 댓글을 달 수 없다. 승인된 계정에만 수의사 표시를 부여한다.

**COM-02 신고·운영 조치**

- [확정] 사용자·게시글·댓글 신고를 접수하고 관리자가 검토·처리한다.
- **수용 기준:** 신고자 정보가 신고 대상자에게 공개되지 않는다. 운영 조치 이후 관련 목록·상세에 동일한 노출 정책이 반영된다. 관리자 처리 결과와 사유를 추적할 수 있다.

[미정] 대댓글 깊이, 좋아요·취소 정책, 콘텐츠 변경·삭제 및 신고 조치 절차는 해당 기능 개발 전에 질문한다.

## 7. 상담 상태와 예외 처리

### 7.1 지정 예약 단계별 코인과 권한

| 단계(제품 흐름, 내부 enum 아님) | 확정 코인 처리 | 수의사 건강 정보 접근 |
|---|---|---|
| 예약 요청 | 즉시 차감 | 간단한 건강 상태만 |
| 예약 승인 | 차감 유지 | [확정] 해당 반려동물 전체 건강 기록. [미정] 구체적인 포함 항목·변경분 공유·복수 예약 판단은 D05 |
| 예약 거절 | 전액 코인 반환 | [미정] 기록·요약·연결 정보의 유지 및 종료 범위(D04·D05·D06) |
| 상담 취소 | 전액 코인 반환 | [미정] 기록·요약·상담 연결 권한의 유지 및 종료 범위(D04·D05·D06) |
| 상담 완료 | 사용 확정 | [확정] 해당 상담에 따른 전체 건강 기록 권한 종료, 해당 상담 일지는 계속 조회. [미정] 다른 승인 예약이 함께 있을 때의 권한 판단(D05) |

각 행은 제공 PRD의 처리 결과를 구분한 것이며 모든 셀을 확정한 표가 아니다. 내부 상태명, 추가 상태, 상태 전이 가능 조건·처리 주체·기한의 미정 부분은 D03·D04에서 결정한다. 담당 수의사의 승인·거절(CON-02)과 수의사의 직접 완료(CON-04) 등 이미 정한 처리 주체는 유지한다. 승인·거절·취소·완료를 구현할 때 코인 처리와 권한 처리를 각각 확인한다. 전액 코인 반환이 기록 접근 종료 시점이나 상담 연결 차단 시점을 자동으로 확정하지 않는다.

### 7.2 위치 기반 즉시 상담의 단계

| 단계 | 서비스 동작 | 미정 항목 |
|---|---|---|
| 즉시 상담 요청 | 보호자가 수단을 선택해 제출하면 요청 접수 기준 0초 500m, 10초 1km, 20초 1.5km, 30초 5km, 40초 10km로 단계별 탐색한다. 매칭이 성립하면 탐색을 종료한다. 전체 대기는 최초 요청 접수부터 최대 60초다. 각 단계에서 즉시 상담 요청 대기 화면을 띄운 대상 수의사의 실시간 목록에 요청을 동시에 추가한다. 반경 확대 시 이미 전달받은 수의사의 목록에는 유효한 기존 요청 한 건을 유지하고, 새로 알림 대상이 된 수의사의 목록에만 추가한다. 이 단계에서는 코인을 차감하지 않는다. | 위치 확인, 거리 산정과 단계별 알림 대상 제한(D17), 요청 알림 정보(D05) |
| 수의사 수락 | 진행 중인 상담이 있는 수의사는 새 즉시 상담을 수락할 수 없다. 최초 수락자 한 명을 확정할 때 코인을 한 번 차감하고 보호자가 선택한 수단으로 연결한다. 매칭이 성립하면 다른 수의사의 대기 목록에서 요청이 즉시 사라진다. | 차감 실패 처리(D17) |
| 미매칭·취소 | 요청 접수 후 60초까지 매칭이 성립하지 않으면 미매칭으로 종료한다. 요청은 수의사의 대기 목록에서 즉시 사라지고 보호자에게는 안내창을 표시한다. 모서리의 닫기(X)는 안내창만 닫고, 보호자가 다시 신청하면 새 매칭을 시작한다. 보호자가 매칭 전에 취소하면 수의사의 대기 목록에서도 요청이 즉시 사라진다. 미매칭과 매칭 전 취소는 잔액을 유지한다. 매칭 후 취소가 성립하면 차감한 코인을 전액 반환한다. | 취소 시점·허용 조건(D04·D17) |
| 상담 완료 | 담당 수의사가 완료 처리한다. | 상담 수단별 연결 종료·재연결과 이력 보관(D06) |

### 7.3 개발 전에 사람에게 질문할 항목 [미정]

- 수의사 응답 기한은 얼마이며, 미응답·예약 시각 경과 시 어떻게 처리하는가?
- 누가 언제까지 취소할 수 있는가? 상담 시작 이후 중단은 어떻게 처리하는가?
- 보호자·수의사 불참, 연결 실패, 장시간 통화, 완료 미처리는 어떻게 처리하는가?
- 예약 시간이 겹치는지 어떤 기준으로 판단하는가?
- 진행 중·만료 등 추가 상태가 필요한가? 상태별 전이 주체와 조건은 무엇인가?
- 완료 오처리, 완료 후 분쟁·환불은 어떻게 처리하는가?
- 정지·탈퇴 계정의 진행 중 예약은 어떻게 처리하는가?

답변 전에는 자동 만료, 취소 제한, 불참 시 코인 몰수, 자동 완료 등 미확정 동작을 구현하지 않는다. 서로 독립적인 확정 기능은 계속 개발할 수 있다.


## 8. 정보 접근 정책

### 8.1 확정된 접근 원칙

| 대상 | 허용 범위 |
|---|---|
| 보호자 | 본인 반려동물의 기록과 본인 상담·일지 |
| 예약 요청을 받은 수의사 | 반려동물의 간단한 건강 상태 |
| 예약을 승인한 수의사 | 해당 반려동물의 전체 건강 기록. 구체적 포함 항목·변경분 공유는 D05 미정 |
| 상담 완료 후 담당 수의사 | 해당 상담에 따른 전체 건강 기록 접근 종료, 해당 상담 일지 계속 조회. 다른 승인 예약과의 관계는 D05 미정 |
| 관리자 | 회원·인증·상담·결제·정산·커뮤니티·신고 운영 기능 |

서버에서 역할·당사자·상담 상태를 검증하고, 파일 주소나 다른 객체 ID를 통한 우회 접근도 차단한다. 상담 완료 후 일지 조회가 건강 기록의 재열람 권한을 부여해서는 안 된다. 거절·취소 후 접근은 확정 권한표에서 누락된 기본 허용이나 기본 차단으로 해석하지 않고 8.2의 미정 질문으로 처리한다. ‘전체 건강 기록’은 범주에 대한 확정이며 기본 정보·접종·진료·미디어·다른 상담 일지의 구체 포함 범위는 D05 답변이 필요하다.

즉시 상담 요청을 받은 수의사에게는 건강 요약과 건강 기록을 표시하지 않는다. 매칭 후에도 즉시 상담으로 기존 건강 기록에 대한 열람 권한을 부여하지 않는다. 알림을 받은 것만으로 상담 참여 권한이 생기지 않는다.

### 8.2 권한 기능 개발 전에 사람에게 질문할 항목 [미정]

- 요청 단계의 ‘간단한 건강 상태’에는 어떤 필드를 포함하는가?
- 승인 후 ‘전체 건강 기록’에 기본 정보, 접종·진료, 미디어, 다른 상담 일지를 어디까지 포함하는가?
- 승인 후 추가·수정·삭제된 기록은 어떻게 공유하는가?
- 거절·취소 이후 예약 요약과 연결 정보는 어디까지 유지하는가?
- 같은 수의사가 같은 동물의 여러 승인 예약을 가진 경우 권한은 어떻게 판단하는가?
- 관리자별 건강 정보·면허 원본·상담 일지 조회 범위는 무엇인가?
- 공유 안내·동의 절차, 데이터 보관·삭제, 임시 파일 접근 유효 기간은 어떻게 정하는가?

관련 질문은 D05를 중심으로 D04·D06·D11과 함께 관리한다. 완료 시 해당 상담의 권한 종료는 확정이지만 다른 승인 예약이 남은 경우 수의사 계정 전체의 기록 접근까지 종료하는지 여부는 미정이다.

답변 전에는 임의의 요약 필드나 관리자 전체 열람 권한을 기본값으로 부여하지 않는다.

## 10. 공통 품질 요구사항과 미결정 항목

### 10.1 보안·정보 보호

- 모든 비공개 데이터와 파일에 서버 측 소유권·역할·상담 상태 검사를 적용한다.
- 전송 구간을 보호하고 자격 증빙·전화번호·결제 식별정보의 저장·조회 권한을 제한한다.
- 결제 민감정보를 직접 수집하는 대신 선택한 결제 제공 업체의 적절한 처리 방식을 사용한다.
- 권한 변경, 관리자 조치, 결제·코인·정산 조정을 감사 가능하게 남긴다. 로그에 건강 기록 본문·면허 원본·실제 전화번호를 그대로 남기지 않는다.
- 기록·미디어·상담 일지·면허·결제 자료별 보관 및 파기 기준을 출시 전 확정한다.

### 10.2 신뢰성과 복구

- 결제 통지·차감·반환·완료·정산 처리의 중복 실행이 결과를 중복시키지 않아야 한다.
- 외부 연동 실패와 처리 지연을 감지하고 원거래 기준으로 대사·재처리할 수 있어야 한다.
- 백업·복구 절차와 목표 복구 시점·시간을 정하고 실제 복구를 검증한다.
- 운영자가 실패 예약, 미반환 건, 미작성 일지, 지급 실패를 식별할 수 있어야 한다.

### 10.3 성능·사용성

- 건강 기록·수의사·상담·커뮤니티 목록은 데이터 증가에 대응하는 페이지 조회를 제공한다.
- 목표 동시 사용자·데이터 규모·응답시간 기준과 측정 환경은 개발 완료 전에 확정한다. 수치 미정 상태를 성능 검증 완료로 간주하지 않는다.
- PC·모바일 반응형 웹에서 주요 흐름을 완료할 수 있어야 한다. 지원 화면 크기와 브라우저별 검증 범위는 미정이며 해당 화면 개발 전 질문한다.
- 입력 필드의 이름·오류 안내, 키보드 조작, 명확한 버튼 상태를 제공한다. 상태는 색상만으로 구분하지 않는다.
- 중복 클릭으로 결제·예약·일지가 중복 생성되지 않으며, 통신 실패 후 입력 내용을 가능한 범위에서 보존한다.
- 지원 브라우저·버전은 출시 전 확정한다.

## 12. 미결정 정책과 결정 시점

아래 결정 항목의 미확정 세부값은 모두 미정이다. 같은 주제의 기존 확정 원칙까지 미정으로 되돌리는 표는 아니다(예: 동일 상담 요금, 거절·취소 시 코인 전액 반환, 완료 시 해당 상담의 기록 권한 종료는 유지). 해당 기능 개발 착수 전에 사용자 또는 지정된 담당자에게 질문하여 답변을 받은 뒤 확정한다. 담당 역할은 질문을 전달할 분야를 뜻하며, 실제 결정자는 사람이 지정한다. 답변이 없으면 해당 정책에 의존하는 부분은 구현하지 않고 독립적인 작업을 진행한다.

## 13. 개발 착수 절차

1. 개발 요청에 기능 ID, 목적·범위, 적용 공통 정책의 절 번호, 관련 D ID, 수용 기준·Q ID를 적는다. 6.11에서 연결된 기능도 확인한다.
2. 미정 질문이 해당 작업에 영향을 주는지 구분한다. 영향을 받는 동작은 사람에게 질문하고 답변 전 구현·QA 기대값 확정을 보류한다. 질문과 무관한 확정 작업은 진행할 수 있다.
3. 답변과 결정자·결정일·사유를 해당 D 항목 및 15장 변경 이력에 남기고 관련 기능·화면·권한·상태·금전 처리·검증 기준을 함께 갱신한다. 외부 검토가 필요한 항목은 검토 여부도 구분한다.
4. 확정된 범위만 구현·검증한다. 내부 상태·API·DB·기술 선택은 별도 상세 설계에서 사람과 합의하며 이 PRD의 표를 물리 설계나 enum으로 그대로 확정하지 않는다.
5. 결과에는 기능 ID·Q ID별 실행한 검증과 결과, 보류된 D ID, 실제 서버·DB·외부 연동의 미검증 범위를 남긴다. 개발 순서·일정·인력 배정은 별도로 협의한다.

**개발 요청에 붙이는 예시**

> 이 PRD를 기준으로 `CON-04`의 상담 완료 처리만 개발해줘. 7.1과 8.1의 상태·권한 규칙을 적용하고, 복수 승인 예약에 관한 `D05`는 답변 전 보류해줘. `Q05`, `Q12`, `Q15`에서 이번 범위에 해당하는 검사 결과와 미검증 항목을 알려줘.

| Q17 | 정지·탈퇴와 신규 행위·진행 중 예약·잔액·정산 | 정지 수의사의 신규 상담 대상 선택·신규 예약은 차단. 그 밖의 역할별 신규 행위와 정지·탈퇴 후 기존 거래·잔액·정산 처리 범위는 D04·D11 답변 후 검증. 예약·코인이 유실되지 않고 처리·추적 가능하며 모든 신규 행위의 일괄 차단을 선확정하지 않음 |
| Q18 | 모바일·PC에서 기록→지정 예약 또는 즉시 상담→상담 후속 흐름 | 주요 버튼·입력·상태·오류 안내 사용 가능 |
| Q19 | 거리 기준 알림, 동시 수락, 미매칭 | 요청 접수 기준 0초 500m, 10초 1km, 20초 1.5km, 30초 5km, 40초 10km로 확대하며 각 단계에서 즉시 상담 요청 대기 화면을 띄운 대상 수의사의 실시간 목록에 요청을 동시에 추가한다. 반경 확대 시 이미 전달받은 수의사의 목록에는 유효한 기존 요청 한 건을 유지하고, 새로 알림 대상이 된 수의사의 목록에만 추가한다. 대기 화면이 닫혔거나 다른 탭을 보고 있거나 화면이 잠겼을 때는 새 요청을 표시하지 않는다. 요청이 여러 건이면 실시간 목록에 각각 표시되고, 수의사는 그중 한 요청을 선택해 수락할 수 있다. 요청 목록에는 상담 수단, 반려동물 종류, 최초 요청의 60초 기한을 기준으로 한 수락 가능 남은 시간이 표시된다. 거리와 반려동물 건강 요약·기록은 표시되지 않는다. 지정 예약 또는 즉시 상담을 진행 중이면 화면이나 서버 요청을 통해서도 다른 즉시 상담을 수락할 수 없다. 상담을 마치고 대기 화면을 다시 열면 새 요청을 받을 수 있다. 매칭이 성립하면 이후 단계로 확대하지 않는다. 10km를 넘는 병원에는 알리지 않는다. 반경을 넓혀도 최초 요청 접수부터 계산한 60초 기한은 연장되지 않는다. 신청만으로 차감하지 않는다. 동시 수락 시 한 명만 확정되고 코인은 한 번만 차감된다. 매칭이 확정되면 다른 수의사의 실시간 대기 목록에서 해당 요청이 즉시 사라진다. 요청 접수 후 60초까지 매칭이 성립하지 않으면 보호자에게 안내창을 표시하고, 수의사의 대기 목록에서는 요청이 즉시 사라진다. 보호자가 매칭 전에 취소해도 수의사의 대기 목록에서 요청이 즉시 사라진다. 만료되거나 취소된 요청은 이후 수락으로 매칭하거나 차감할 수 없다. 미매칭과 매칭 전 취소는 잔액이 유지된다. 미매칭과 잔액 부족은 각각의 안내 문구로 구분한다. 미매칭 안내창의 모서리 X를 누르면 창만 닫힌다. 보호자가 즉시 상담을 다시 요청하면 새 매칭을 시작한다. 매칭 후 취소가 성립하면 차감액을 전액 한 번 반환한다. 차감 실패와 취소 허용 조건은 D17 답변 후 검증한다. |
| Q20 | 채팅·화상·안심번호 전화 연결, 제3자 접근 | 두 상담 유형 모두 신청 버튼을 누르면 세 수단이 표시되고, 보호자가 고른 수단으로 상담 당사자만 연결된다. 연결 실패 시 안내와 재연결 동작을 확인한다. 전환·기록의 기대값은 D06 답변 후 검증한다. |
| Q21 | 상담 완료 확인창과 보호자 신고 | 지정 예약·즉시 상담 모두 상담 완료 버튼을 누르면 확인창이 열린다. 일반 완료와 신고 접수 성공은 각각 상담을 한 번 완료 처리하고 일지 작성으로 이동한다. 담당 수의사만 해당 상담의 보호자를 신고할 수 있고, 관리자는 신고와 관련 상담을 확인할 수 있다. |

기능별 연결표(6.11)에서 각 Q에 관련된 요구사항·D ID를 함께 확인한다. 미정 정책과 관련된 기대 결과는 정책 확정 후 더 세분화하며, 해당 부분은 미실행·정책 대기로 구분하고 통과 처리하지 않는다. 테스트는 각 조건을 독립적으로 확인하고 실패 복구와 기존 흐름 보존을 포함한다.
