# 프로젝트 기억 인덱스

| 기록 | 찾을 키워드 | 설명 |
| --- | --- | --- |
| [PRD](../../prd.md) | 요구사항, 반려동물, 전화 상담, 권한, 결제 | 제품 요구사항·정책과 미정 항목 |
| [FACTS](FACTS.md) | 스택 없음, 환경, 검증 근거 | 코드·설정·실행으로 확인한 사실 |
| [DECISIONS](DECISIONS.md) | 하네스, 로컬 상태, 훅, 도구 방식 | 채택 이유와 적용 범위 |
| [PITFALLS](PITFALLS.md) | PF-001 이식성, PF-002 포인터, PF-003 훅 shadow, PF-004 필드 타입 | 재현·해결된 문제와 방지 검증 |

필요한 항목만 읽는다. 로컬 세션은 `.codex/local/sessions/`에 있으며 공유 장기 기억과 다르다. 추측·미확인 내용은 해당 세션에만 둔다.

검증된 사실에는 근거·적용 범위·확인 날짜·재확인 조건을 남긴다. 사용자 정정이나 해결된 문제를 승격할 때 기존 항목을 먼저 찾고, 현재 코드가 다르면 코드·실행을 확인해 기록을 정정한다. 개인 취향은 팀 정책으로 승격하지 않는다.

실제 사례에는 ID, 발생 조건·증상, 확인된 원인, 올바른 처리, 관련 파일·검증 근거, 재발 횟수, 방지 장치, 상태·적용 범위를 기록하고 여기 링크한다. 같은 원인은 같은 ID에 근거와 재발 횟수를 추가한다.

방지 장치는 스타일이면 기존 formatter/linter, 결과 오류면 회귀 테스트, API·DB 계약이면 계약·통합 테스트, 명확한 실행 전 금지면 훅 후보, 완료 누락이면 검증 스킬·CI, 판단 문제면 결정·리뷰를 우선한다. 피해·자동 판별 가능성·오탐 가능성을 고려하며 횟수만으로 훅을 만들지 않는다. 중대한 문제는 한 번이어도 회귀 검증을 둔다.
