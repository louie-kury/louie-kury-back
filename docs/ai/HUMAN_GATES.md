# 대화에서 선택하고 확인하기

- 사람이 개발 방향과 이유를 고른다. AI가 정한 답을 승인만 받는 방식으로 진행하지 않는다.
- “설계가 좋다”와 “코드를 작성해도 된다”를 구분한다. 구현 전에 변경할 범위를 설명하고 사람의 결정을 기다린다.
- 계획은 선택한 안·장단점·이유·미정 사항을 남긴다. 선택하지 않은 내용을 결정된 것처럼 기록하지 않는다.
- 요구사항이나 중요한 설계가 바뀌면 다시 이야기한다. 정해진 작은 범위 안에서는 확인을 불필요하게 반복하지 않는다.
- PR의 코드와 설명은 팀원이 검토한다. 리뷰를 반영한 뒤 다시 검토받고, 최종 머지는 사람이 한다. AI는 Approve·자동 머지·머지 큐·보호 규칙 우회를 대행하지 않는다.

별도 승인 프로그램·긴 확인 문자열·로컬 승인 JSON은 사용하지 않는다. 과거 승인 기록은 현재 결정으로 재사용하지 않는다. GitHub 권한과 보호 설정은 별도로 관리하며, 문서만으로 서버 접근이 차단되는 것은 아니다.
