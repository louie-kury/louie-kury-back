## 스케일아웃 설계 때 확인할 논점

실제 설계를 검토할 때만 읽는다. 아래는 구현 지시가 아닌 검토 항목이다.

- 인스턴스 메모리에 세션·상담 상태·중복 방지 상태를 의존하는지, 여러 인스턴스에서 일관성을 어떻게 유지할지.
- 상담 요청 재시도·동시 수락·취소 경쟁에서 중복 상담·중복 통화가 발생하는지. DB 제약·트랜잭션·멱등성의 책임을 어디에 둘지.
- 외부 통화 연동이 생기면 타임아웃·재시도·콜백 순서 변경·서명 검증·중복 수신을 어떻게 검증할지.
- DB 연결 수, 병목, 공유 저장소·파일 업로드, 로드밸런싱, 종료 중 요청, 관측 지표와 실패 복구.
- 실제 선택은 근거와 함께 [DECISIONS](ai/memory/DECISIONS.md)에 남긴다. 기술 스택이나 분산 시스템 구성은 아직 선택하지 않았다.
